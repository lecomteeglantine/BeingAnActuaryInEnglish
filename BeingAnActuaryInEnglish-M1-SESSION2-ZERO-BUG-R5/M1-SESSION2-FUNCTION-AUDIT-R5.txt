FUNCTIONAL BUGS FIXED IN R5
1. Anti-double-click lock was global in R4.
   - A legitimate fast sequence such as Enter museum -> choose 3/4 -> Start Gallery I could have the Start click silently ignored.
   - Review -> Save could be ignored for the same reason.
   FIX: action-specific locks. Repeated activation of the same action is blocked, but different consecutive actions never block one another.

2. Practice timer leaked across a restart/review cycle.
   - Example: practise for 20 seconds, restart museum, complete a new game: the next Final could inherit 1:40 instead of 2:00.
   FIX: timer state resets silently whenever the team leaves Final for review and whenever the museum is restarted.

3. Rapid double-click on Start/Pause timer could toggle twice and appear not to start.
   FIX: dedicated timer-action debounce.

4. Rapid double-click on sound controls could toggle twice and return to the original state.
   FIX: dedicated sound-control debounce.

5. Auto-save recovery bug.
   - R4 permanently stopped attempting localStorage writes when storage was unavailable at initialisation.
   FIX: every save retries storage; if storage becomes available again, the badge returns to Local auto-save automatically.

6. Loss-risk when browser storage is unavailable.
   FIX: browser navigation/reload now triggers the standard unsaved-work warning while a game is in progress and auto-save is unavailable.

7. Small-screen horizontal overflow risk from default <figure> margins in the gallery object strip.
   FIX: object figures now explicitly use margin:0 and min-width:0. Tested at 320, 360, 560, 768, 1024 and 1440 px.

8. Score wording was ambiguous.
   - The side score intentionally includes only explicitly saved galleries so students cannot probe answers before validating them.
   FIX: label changed from Current score to Saved score.

9. Deployment/cache hardening.
   - Session 2 now loads versioned R5 JS/CSS filenames.
   - M1 -> Session 2 and Session 2 -> game links include an R5 query marker to reduce stale-cache navigation after GitHub uploads.

10. Final pitch live guidance strengthened.
   - Final word counter now shows the 160-210 word target.
   - Long scripts are flagged consistently with the speaking-time warning.
